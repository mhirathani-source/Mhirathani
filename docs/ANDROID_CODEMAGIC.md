# Android release build with Codemagic

The Android project is generated by Expo inside Codemagic. No generated native
folder, signing key, or production database data is committed to this project.

## Connect and configure Codemagic

1. Connect the repository containing this project to Codemagic. The current
   workspace Git remotes are Replit-managed and do not by themselves connect a
   Codemagic account.
2. Add a Codemagic variable group named `prime_boxing_mobile` with
   `CLERK_PUBLISHABLE_KEY`. Use the production Clerk publishable key; never add
   `CLERK_SECRET_KEY`, a database URL, or a password to the mobile build.
3. Create or import a durable Android release keystore in Codemagic and make its
   signing configuration available under the reference `prime_boxing_android`.
   Keep that same keystore for all future releases of this package.
4. Start the `prime_boxing_android_release` workflow. It generates Android
   files on the remote builder, installs the repository's frozen pnpm lockfile,
   and creates a signed release APK.

The APK is emitted at
`artifacts/prime-boxing-native/android/app/build/outputs/apk/release/`.
Codemagic exposes it as a build artifact. This configuration does not publish
it to a public file host or create a public direct-download URL.

## Production access requirement

The app calls the existing API using `EXPO_PUBLIC_DOMAIN` and does not contain
database credentials. The production app/API must be reachable over HTTPS
without a Replit deployment password gate; the club's own Clerk sign-in and
server-side permissions must remain enabled. Verify this in the deployment
settings before distributing the APK.

## What has not been verified

The workflow must run in the connected Codemagic account to verify native
compilation and signing. Clerk sign-in/out and persistence also require a
physical device or simulator with an authorized test account. The local JS
bundle export is not proof of either.
