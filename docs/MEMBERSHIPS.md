# تشغيل إدارة المشتركين والاشتراكات

> الصلاحيات: إدارة الاشتراكات والأسعار والمدفوعات والإيصالات والحذف النهائي للمدير فقط. الموظف يرى ويعدّل البيانات الأساسية للمشترك عبر ملف غير مالي. راجع [سياسة الصلاحيات](SECURITY_RBAC.md).

## بيانات المشترك

- من «المشتركون» اختر «تعديل»، أو افتح ملف المشترك واختر «تعديل البيانات». تظهر القيم المحفوظة: الاسم والهاتف والبريد وتاريخ الميلاد والملاحظات وتفعيل الحساب.
- تاريخ الميلاد اختياري ولا يقبل تاريخًا مستقبليًا. الهاتف يُحفظ دون المسافات والأقواس والشرطات، ويجب ألا يتكرر بين المشتركين.
- بعد الحفظ تظهر النتيجة وتُحدّث القوائم والملف دون إعادة تحميل الصفحة. عند الخطأ تبقى المدخلات متاحة للتصحيح.
- تفعيل حساب المشترك منفصل عن حالة كل اشتراك. الأرشفة تعني تعطيل الحساب، وليست حذفًا للديون أو إلغاءً للمدفوعات.

## الحذف والأرشفة

- الحذف النهائي للمدير فقط، وبعد تأكيد يتضمن اسم المشترك.
- يُسمح بالحذف للمشترك غير المرتبط باشتراكات أو حركات مالية أو تذكيرات. لا تستخدم قاعدة البيانات حذفًا متسلسلًا لهذه السجلات.
- عند وجود ارتباط يعرض النظام سبب المنع وخيار الأرشفة الذي يحتاج إلى تأكيد مستقل بالضغط عليه. يمكن إعادة التفعيل لاحقًا.
- يبقى أثر تدقيق لعملية الحذف دون حذف سجل التدقيق نفسه.
- لا تقبل الأرشفة إنشاء أو تجديد اشتراك للمشترك المعطّل، كما يتوقف إرسال تذكيرات واتساب إليه. تبقى الاشتراكات القديمة والمدفوعات والديون قابلة للعرض والتحصيل.

## الاشتراكات

- يمكن الإنشاء من صفحة الاشتراكات أو ملف المشترك. يدعم اختيار الباقة والبداية والخصم والدفعة الأولى وطريقة الدفع.
- يمكن البحث عن المشترك بالاسم أو الهاتف في نموذج الإنشاء. فتح النموذج من ملف المشترك يختاره مسبقًا، حتى لو لم يكن ضمن أول نتائج القائمة.
- يمنع النظام تداخل فترتين للباقة نفسها والمشترك نفسه ما لم يكن الاشتراك الآخر ملغيًا. الحماية تشمل الطلبات المتزامنة، وليس تعطيل الزر فقط.
- تعديل الاشتراك للمدير وعلى الاشتراك الحالي النشط أو الموقوف مؤقتًا فقط. يمكن تصحيح الباقة والتاريخين والسعر؛ لا تُعدّل إيصالات أو مبالغ دفعات سابقة بهذه الشاشة.
- لا يمكن أن يقل السعر عن صافي المدفوع والخصم المسجّل. يجري تدقيق التصحيح مع القيم السابقة واللاحقة.
- تُدار الحالة بأزرار الإيقاف والاستئناف والإلغاء. الاستئناف يضيف مدة الإيقاف إلى نهاية الاشتراك، بشرط عدم تداخل الفترة الناتجة مع اشتراك آخر للباقة نفسها.
- التجديد ينشئ سجلًا جديدًا مرتبطًا بالسابق، ولا يغيّر ثمن الاشتراك السابق أو دفعاته أو دينه. تحصيل دفعة التجديد عملية مستقلة بعد الإنشاء.
- لا يمكن تجديد السجل السابق مرتين. استخدم أحدث تجديد عند التجديد لاحقًا.
- الإلغاء لا يعيد أموالًا ولا يمحو دينًا. يبقى الرصيد المستحق ظاهرًا وقابلًا للتحصيل، بما في ذلك في لوحة التحكم.
- الاشتراكات المنتهية والملغاة تاريخية ولا تُعدّل بالسعر والتاريخ بأثر رجعي.

## البيانات والترحيلات

التغيير في المخطط إضافي فقط: تاريخ ميلاد اختياري للمشترك، ومعرّف مصدر تجديد اختياري مع فهرس يمنع تكراره. لا يوجد حذف أو إعادة إنشاء لجداول أو مسح للسجلات الحالية، ولا تحويل لسجل التجديدات القديمة بالتخمين.

تُحفظ التواريخ اليومية كسلاسل `YYYY-MM-DD`، والمبالغ كأعداد صحيحة بالفلس الأردني. جميع التواريخ التشغيلية تستخدم `Asia/Amman`.

ملف الترحيل موجود في `lib/db/drizzle/`. تُطبّق تغييرات قاعدة التطوير بأدوات Drizzle، أما قاعدة Replit الإنتاجية فتتبع مسار النشر المعتاد. لا توجد أوامر DDL عند تشغيل الخادم.

## التحقق

```bash
pnpm run typecheck
pnpm --filter @workspace/scripts exec tsx --test ../artifacts/api-server/src/lib/membership.test.ts
```

الاختبارات الآلية الصغيرة لا تُنشئ سجلات أعمال. اختبارات المتصفح يجب أن تستخدم حسابات وبيانات تطوير مؤقتة مميزة، وأن تنظّف سجلاتها فقط دون المساس ببيانات النادي. لا تختبر الحذف على مشترك حقيقي أو ترسل رسائل واتساب ضمن اختبار المشتركين.
