# تقرير تطوير لوحة التحكم والصلاحيات

## ما تم إصلاحه وإضافته

- حفظ حساب الموظف الجديد في PostgreSQL بحالة انتظار بدل منعه دون إنشاء طلب يستطيع المدير رؤيته.
- لوحة «لوحة التحكم والإعدادات» للمالك، مع الموافقات والرفض والإيقاف وإعادة التفعيل وإشعار بعدد الطلبات.
- أدوار أساسية ومخصصة وصلاحيات لكل عملية واستثناءات لكل مستخدم. الصلاحية المالية تُمنح صراحةً؛ لا يكفي اسم الدور.
- حماية API والروابط المباشرة، وفصل واجهات الاشتراكات التشغيلية عن واجهات الأسعار والتحصيل والديون.
- حماية حساب المالك من فقد دوره أو تعطيله أو حذفه، دون تغيير هويته أو كلمة مروره.
- إصلاح أدوات المشتركين والباقات والأرشفة وتصحيح الاشتراكات والمدفوعات والإيرادات والمصاريف واستحقاقات الرواتب.
- عكس التحصيل بإضافة استرداد، وعكس الحركة المالية بقيد سالب من النوع نفسه، ومنع تكرار العكس أو تعديل أصل معكوس.
- تصحيح تجميع الصندوق لاستبعاد الحركات المشتقة المكررة، وحساب الاستردادات والإيرادات والمصاريف الفعلية.
- إعدادات دائمة للحقول المطلوبة وطرق الدفع وحد الخصم والسنة المالية وسياسة التجديد وأيام التذكير.
- تصدير CSV محمي بالصلاحيات وطباعة/PDF من المتصفح للمخولين، وسجل تدقيق بالقيم السابقة واللاحقة.
- نسخ أعمال مشفرة، استيراد وتحقق ومعاينة، وتأكيد صريح قبل الاستعادة ونسخة أمان قبلها. الاستعادة لا تمس الهوية والصلاحيات وسجل التدقيق.

## الاختبارات المنفذة

### المتصفح مع Clerk وقاعدة البيانات الفعلية في التطوير

- استخدمت هوية المالك الحالية دون تعديلها، وهوية موظف اختبار مستقلة.
- انتظار الموافقة وظهور الطلب واعتماده بالدور نفسه، ثم تفعيل صلاحية عرض التقارير فقط.
- منع الوصول المالي غير الممنوح عبر الصفحات وAPI، حتى مع تزوير ترويسة الدور.
- السماح بعرض التقرير دون تصديره، ثم الإيقاف والرفض وإزالة البيانات من الواجهة.
- حماية دور المالك وحالته، وفحص شاشة الهاتف.
- إضافة مشترك وتعديله وحذف سجل غير مرتبط، ثم إنشاء باقة واشتراك وتحصيل وتصحيح سعر ومدة الاشتراك.
- عكس دفعة مع إبقاء الإيصال والاسترداد، ورفض العكس الثاني؛ بقاء التصحيح بعد الخروج والدخول مجددًا.
- رفض حذف مشترك مرتبط وأرشفته مع حفظ تاريخه.
- عكس مصروف دون إيراد وهمي؛ رجوع الصندوق والتقرير إلى قيمة البداية ورفض تعديل الأصل المعكوس.

### اختبارات آلية

- نجح 13 اختبارًا مميزًا للوحدات والتكامل: التواريخ وعقود العضويات، حماية المسارات والصلاحيات والتصدير، الحساب النقدي، التشفير، والاستعادة.
- اختُبرت الاستعادة الحقيقية في معاملة PostgreSQL أُلغي تنفيذها بعد التحقق؛ لم تُستبدل بيانات العمل نهائيًا. رُفض الملف المعدّل والمعاينة القديمة حتى عند تغيير البيانات دون حدث تدقيق.
- اختُبرت عبر HTTP محلي معالجات إنشاء الدور وتعديله وحذفه، ومنع حذف دور مرتبط، ومنع الموظف من النسخ، وإنشاء النسخة وتنزيلها واستيرادها ومعاينتها ورفض تأكيد خاطئ.
- معالج HTTP المحلي اختبار للمعالجات بهوية اختبار محقونة؛ اختبار المصادقة الفعلي منفصل ونُفذ عبر Clerk في المتصفح.
- نجح فحص TypeScript وبناء الواجهة، وعمل API بعد إعادة تشغيله. فُحصت صفحة البداية على الهاتف.

## حدود يجب معرفتها

- الاختبارات في التطوير، وليست اختبار إنتاج بعد النشر. حساب الموظف الاختباري موقوف، وسجلات الاختبار المالية المرتبطة محفوظة في التطوير لأغراض التدقيق؛ لم تُعدّل سجلات العملاء السابقة.
- لا ندّعي اختبار كل تركيب ممكن من الصلاحيات أو كل شاشة على كل جهاز. الأدوات الجديدة لاستحقاقات الرواتب والسياسات العامة تحتاج اختبار قبول تشغيلي إضافيًا لحالات النادي الخاصة.
- لا يُحذف راتب مصروف ولا يُخفض عن المصروف. عكس دفعات رواتب مصروفة بمسار مخصص غير متاح في هذه المرحلة؛ يُمنع عكس حركتها العامة منفصلة عن سجل الراتب.
- كان إصدار هذا التقرير يصف ربط Meta. التحديث الحالي يستبدله برسائل WhatsApp يدوية عبر رابط محادثة، بلا API أو مؤقت أو ادعاء بالتسليم؛ انظر `docs/MOBILE-AND-WHATSAPP.md`.
- النسخة القابلة للتنزيل نسخة أعمال، وليست نسخة كاملة للهوية والأدوار والتدقيق. يلزم نسخ PostgreSQL خارجي دوري وخطة احتفاظ وتجربة تعافٍ منفصلة.
- النظام يقدم معاملات نقدية وتقارير واستحقاقات؛ ليس دليل حسابات وقيودًا مزدوجة كاملة.
- لم يُنشر التحديث تلقائيًا. يبقى الإنتاج على نسخته الحالية إلى أن يُنشر التحديث ويُفحص دخول المالك والصلاحيات هناك.
