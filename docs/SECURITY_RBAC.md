# صلاحيات الإدارة والبيانات المالية

## مصدر الصلاحيات

تسجيل الدخول عبر Clerk، لكن قرار الصلاحية من `club_users.role` في PostgreSQL، وليس من المتصفح أو بيانات يرسلها المستخدم. الأدوار المدعومة حاليًا `admin` و`staff`. القيمة الافتراضية الموجودة أصلًا `staff`. الحساب المسجّل في Clerk دون اعتماد في جدول النادي لا يحصل على صلاحيات مالية.

## مصفوفة الوصول

| الوظيفة | المدير | الموظف |
|---|---|---|
| قائمة المشتركين وإضافة وتعديل البيانات الأساسية والأرشفة | نعم | نعم |
| الملخص التشغيلي دون مبالغ | نعم | نعم |
| ملف المشترك الأساسي دون دفعات أو أسعار | نعم | نعم |
| المالية والإيرادات والمصاريف والصندوق والرواتب والموظفون | نعم | لا |
| التقارير والتصدير | نعم | لا |
| الباقات وأسعارها والاشتراكات والمدفوعات والديون | نعم | لا |
| الإيصالات وسجل الدفعات ولوحة التحكم المالية | نعم | لا |
| إعدادات واتساب وسجل الرسائل والإرسال اليدوي | نعم | لا |
| الحذف النهائي للمشترك | نعم، وفق حماية السجل المالي | لا |

حُصرت واتساب بالمدير لأن الرسائل والتفاصيل المسجّلة قد تتضمن بيانات مالية. لم تُحذف أي صفحة أو سجلات مالية.

## حماية الخادم

توجد بوابة مركزية قبل جميع مسارات أعمال API: مستخدم Clerk موثّق، ثم سجل نادي معتمد، ثم المدير فقط افتراضيًا. الاستثناءات غير المالية المحددة بالاسم والطريقة:

- `GET /api/club/session` — معلومات الدور فقط؛ يحتاج تسجيل الدخول.
- `GET /api/club/overview` — أعداد تشغيلية فقط.
- `GET/POST /api/members` — بيانات أساسية فقط.
- `PATCH /api/members/:id` — تعديل البيانات الأساسية فقط.
- `GET /api/members/:id/profile` — ملف أساسي فقط دون اشتراكات أو مدفوعات.

تُسمح `HEAD` للقراءات غير المالية فقط. أي مسار جديد غير مُراجَع يبقى للمدير افتراضيًا، بما فيه المسارات القديمة في `/api/club/finance/*` والمسارات الأحدث في `/api/finance/*`. يعيد الخادم `403` للموظف قبل تنفيذ معالج المسار المالي. يعيد `401` لغير المسجّل. تبقى فحوص المدير المحلية الإضافية كما هي.

لا تُحفظ استجابات الأعمال في كاش HTTP (`private, no-store`). الواجهة تخفي الروابط وتمنع فتحها مباشرة، وتستخدم كاش استعلامات منفصلًا لكل هوية دخول. يُنظّف كاش البيانات المالية عند تغيّر الدور، مع إعادة التحقق دوريًا وعند العودة للنافذة. لا تعتمد حماية الخادم على تحديث الدور في الواجهة.

## حساب المالك

يبقى `CLUB_ADMIN_EMAIL` معرّف المالك الموثوق المضبوط في البيئة، ولا يظهر في الشيفرة أو السجلات. التهيئة تتحقق من تطابق **البريد الأساسي الموثّق لدى Clerk** قبل منح المدير، وتكتب علامة تدقيق لتهيئة المالك مرة واحدة. لا تعيد هذه التهيئة صلاحية سُحبت لاحقًا عمدًا. تعمل في بيئة التشغيل نفسها، لأن هويات Clerk وقواعد التطوير والإنتاج منفصلة.

إذا لم يوجد الحساب الموثّق بعد، ينتظر النظام تسجيل دخول المالك بدل إنشاء كلمة مرور مشتركة أو ترقية أي مستخدم عشوائي. لا تُرقِّ أي حساب بإرسال `role` ضمن طلب من المتصفح.
