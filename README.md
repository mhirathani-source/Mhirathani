# Prime Boxing Academy Management System

نظام ويب عربي لإدارة أكاديمية ملاكمة واحدة. الواجهة باتجاه RTL، والتاريخ المحلي `Asia/Amman`، وتُحفظ المبالغ بالدينار الأردني على هيئة فلس صحيح لتجنّب أخطاء الكسور.

## الحالة الحالية

المتاح الآن: تسجيل الدخول وصلاحية المدير الأول، PostgreSQL وسجل التدقيق، إدارة المشتركين والباقات والاشتراكات والمدفوعات والإيصالات، تسجيل الإيرادات والمصاريف والتصنيفات، سجل الصندوق، الموظفون واستحقاقات الرواتب وصرفها جزئيًا، وتقارير مالية حسب فترة مع الطباعة وتصدير الحركات إلى CSV متوافق مع Excel. لا توجد بيانات تجريبية.

أضيف مخطط الإيرادات والمصروفات الشهري واختصارات العمليات اليومية. كما أضيف إعداد WhatsApp الرسمي والقوالب والتذكير اليدوي وسجل المحاولات وجدولة يومية حسب تاريخ الأردن (قبل الانتهاء بيومين ويوم الانتهاء).

ما يزال غير مكتمل: الحسابات المزدوجة، حسابات دخول الموظفين والصلاحيات التفصيلية، السلف والمكافآت والخصومات، التقارير التشغيلية المتقدمة، النسخ الاحتياطية الآلية، وPWA والنشر الإنتاجي. إرسال واتساب الفعلي غير متحقق بعد، ولا يُعد جاهزًا حتى صلاحية الاتصال واعتماد القوالب وتجربة إرسال بإذن المدير.

## التشغيل

- شغّل واجهة الويب من سير العمل `artifacts/club-manager: web`.
- شغّل الـAPI من سير العمل `artifacts/api-server: API Server`.
- للتحقق من الأنواع: `pnpm run typecheck`
- لمزامنة مخطط قاعدة بيانات التطوير: `pnpm --filter @workspace/db run push`
- لإنشاء ملف ترحيل عند تعديل المخطط: `pnpm --filter @workspace/db run generate`

تُدار قاعدة PostgreSQL من Replit. لا تُدرج بيانات مشتركين تجريبية أو مفاتيح في ملفات المشروع. تغييرات مخطط قاعدة بيانات الإنتاج يجب أن تمر عبر مسار النشر المدعوم، ولا يُنشر التطبيق قبل ضبط المدير الأول والتحقق من تسجيل الدخول.

ملفات Drizzle موجودة في `lib/db/drizzle/`. قاعدة التطوير الحالية تمت مزامنتها بأمر `push`؛ لا تعِد تشغيل ترحيل الأساس `0000_dark_leech.sql` عليها.

## إعداد المدير الأول

1. أنشئ حسابًا من صفحة التسجيل في بيئة التطوير باستخدام البريد الإلكتروني الذي سيُخصّص للمدير.
2. اضبط المتغير غير السري `CLUB_ADMIN_EMAIL` على البريد نفسه من أدوات متغيرات البيئة.
3. سجّل الدخول مجددًا. يُنشأ سجل المدير تلقائيًا فقط للحساب المطابق؛ أما أي حساب آخر فلا يحصل على وصول للنادي.

إعدادات Clerk السرية مُدارة في Replit Secrets. لا تُنشئ كلمة مرور ثابتة أو تشاركها.

## إعداد واتساب وصيانته

1. افتح «واتساب» من قائمة التطبيق. الرمز السري يُدار في اتصال WhatsApp Business داخل Replit، وليس في قاعدة البيانات أو الواجهة.
2. من Meta App Dashboard > WhatsApp > API Setup، انسخ **WABA ID** و**Phone Number ID** (ليس رقم الهاتف نفسه) إلى الشاشة.
3. أرسل القوالب العربية الثلاثة للمراجعة. المتغيرات بالترتيب: `{{1}}` اسم المشترك، `{{2}}` اسم الباقة، `{{3}}` تاريخ الانتهاء. أمثلة القالب المرسلة إلى Meta ليست بيانات مشتركين.
4. اضغط «تحديث الحالات»، وانتظر حالة «معتمد» لكل قالب مطلوب. يلزم إذنا `whatsapp_business_management` و`whatsapp_business_messaging` في اتصال Meta.
5. فعّل الإرسال فقط بعد التأكد من الإعدادات، ثم اختبر التذكير اليدوي على رقم وافق على استقبال الرسالة. لا تُرسل رسائل اختبار للمشتركين دون موافقتهم.
6. راجع سجل التذكيرات في ملف المشترك؛ `accepted` يعني قبول Meta للطلب، وليس التسليم. تأكيد التسليم وقراءة الرسالة يتطلب Webhook رسميًا لم يُنفّذ بعد.

المهمة تفحص المواعيد كل دقيقة في عملية خادم الـAPI، دون جلسة مدير. يجب إبقاء خادم الإنتاج يعمل باستمرار؛ لا نضمن التذكيرات إذا توقف الخادم أو نامت الخدمة. يمنع فهرس قاعدة البيانات تكرار التذكير التلقائي للاشتراك نفسه ونوع التذكير. المحاولات الفاشلة تُحفظ ولا يعاد إرسالها تلقائيًا لتجنب تكرار محتمل؛ يمكن المحاولة يدويًا بعد معالجة السبب. يمنع تكرار المحاولة اليدوية خلال الدقيقة نفسها.

أخطاء Meta: `190` تعني بيانات اتصال غير صالحة/منتهية؛ حدّث الاتصال داخل Replit دون إرسال الرمز في المحادثة. `132001` تعني قالبًا غير معتمد أو لغة غير مطابقة. لم يُنفّذ نشر إنتاجي أو نسخ احتياطي آلي حتى الآن.
